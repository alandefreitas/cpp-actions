Process Coverage

Unified post-test C++ coverage processing pipeline for GCC and Clang.

Supports gcov/lcov (GCC) and llvm-cov (Clang) toolchains, with LCOV filtering, metrics extraction, and optional uploads to Codecov and Coveralls.

Example

steps:
- name: Process Coverage
  uses: alandefreitas/cpp-actions/process-coverage@develop
  with:
    cxx: ${{ steps.setup-cpp.outputs.cxx }}
    build-dir: tests/build
    include: tests/**
    html-report: true
    codecov-token: ${{ secrets.CODECOV_TOKEN }}
    codecov-flags: cpp

Input Parameters

Parameter

Description

Default

trace-commands

Trace commands executed by the workflow.

false

compiler

The compiler family used to build the project.

Determines which coverage pipeline to use: gcc uses gcov/lcov, clang uses llvm-profdata/llvm-cov.

When not provided, the action auto-detects the compiler by running cxx --version (if cxx is set) or by checking which coverage files exist in the build directories (.profraw → clang, .gcda → gcc).

compiler-version

The compiler version used to build the project.

Accepts any version format: a bare major number (14), a full version (14.2.0), a semver range (>=14), or a wildcard (). The action extracts the major version to locate version-matched coverage tools (e.g., gcov-14, llvm-cov-18). When the major version cannot be determined (e.g., ), the action falls back to unversioned tools.

When not provided, the action auto-detects the version from the cxx binary’s --version output, or falls back to unversioned tools.

Typically set from setup-cpp outputs (steps.setup-cpp.outputs.version), cpp-matrix fields (matrix.major or matrix.version), or a literal version number.

cxx

Path to the C++ compiler binary.

Used as a fallback to detect the compiler family and version when compiler or compiler-version are not provided. The action runs cxx --version and parses the output to identify the compiler.

Falls back to the CXX environment variable if not set.

Typically set from setup-cpp outputs (steps.setup-cpp.outputs.cxx).

build-dir

List of build directories to search for coverage data.

For GCC, these directories contain .gcda/.gcno files. For Clang, these directories are searched for .profraw files.

build

include

Glob patterns to include in coverage results.

Only LCOV sections whose source file path matches at least one pattern are kept. Empty list means include all files.

Relative patterns like src/ or tests/.cpp are automatically prefixed with / so they match against the absolute paths in LCOV data without requiring the full workspace path. Use to match within a single directory and ** to match across directories.

exclude

Glob patterns to exclude from coverage results.

LCOV sections whose source file path matches any pattern are removed. Applied after include filtering. Empty list means exclude nothing.

Relative patterns are automatically prefixed with **/, same as include.

summary

Write a coverage summary table to the GitHub Actions step summary.

Includes line, function, and branch coverage metrics. If new-code analysis is available, includes a new-code section.

true

html-report

Generate an HTML coverage report using genhtml.

The report directory path is available via the html-report-dir output for use in subsequent steps (e.g., deploying to GitHub Pages).

false

html-report-artifact

Name for the HTML coverage report artifact.

When set to auto (default), generates a unique name from the compiler and platform (e.g., coverage-report-gcc-linux).

When set to any other value, that value is used as-is.

Set to an empty string to skip artifact upload — the report is still generated and available via the html-report-dir output.

auto

html-report-retention-days

Number of days to retain the HTML coverage report artifact.

30

diff-base

Git ref to compare against for new-code coverage analysis.

The action runs git diff <diff-base>..HEAD to identify which lines were added or modified, then cross-references them with coverage data to report what percentage of new code is covered.

Accepts any valid git ref: a branch name (main, origin/develop), a commit SHA (abc123 or full hash), a relative ref (HEAD~1), or a tag (v1.0.0).

When not provided, the action auto-detects from the GitHub Actions environment: - Pull requests: uses origin/$GITHUB_BASE_REF (the PR target branch) - Push events: uses HEAD~1 (the previous commit)

Requires actions/checkout with fetch-depth: 0 (or enough history to reach the base ref). If the diff cannot be computed (e.g., shallow clone), new-code analysis is silently skipped.

strip-excl-markers

Strip LCOV_EXCL / GCOV_EXCL markers from coverage data.

When enabled, lines marked with LCOV_EXCL_LINE or between LCOV_EXCL_START/LCOV_EXCL_STOP (and GCOV_EXCL equivalents) are removed from the LCOV output. This is useful because some coverage services and tools do not honor these markers natively.

true

binaries

Paths to the instrumented test executables (Clang only).

Clang’s llvm-cov export needs to know which executable produced the coverage data. Each entry is a path or glob pattern pointing to a test binary built with -fprofile-instr-generate -fcoverage-mapping (e.g. build/bin/my_tests, build/test_*).

When not provided, the action searches the build directories for executable files and attempts to use them automatically. Provide this input explicitly when auto-discovery picks up the wrong binaries or when the build directory contains many unrelated executables.

Ignored for GCC pipelines (GCC coverage tools do not need binary paths).

profraw-pattern

Glob pattern to match .profraw files in build directories.

Only used for Clang pipelines. The default matches both default-%p-%m.profraw and default-%b-%p-%m.profraw patterns set by LLVM_PROFILE_FILE.

default-*.profraw

codecov-token

Codecov upload token. If non-empty, uploads coverage to Codecov.

The token can be found in your Codecov repository settings.

codecov-flags

Comma-separated list of Codecov flags to associate with the upload.

codecov-args

Extra arguments to pass to the Codecov CLI upload command.

coveralls-token

Coveralls repo token. If non-empty, uploads coverage to Coveralls.

The token can be found in your Coveralls repository settings.

coveralls-args

Extra arguments to pass to the Coveralls coverage-reporter command.

fail-on-upload-error

Fail the action if a coverage upload (Codecov or Coveralls) fails.

Set to false to treat upload failures as warnings instead of errors. This is useful for forks where coverage tokens may not be available as secrets.

true

Outputs

Output

Description

lcov-file

Absolute path to the final LCOV .info file after filtering.

html-report-dir

Absolute path to the HTML coverage report directory. Empty if html-report is not enabled.

lines-covered

Number of lines with non-zero execution count.

lines-total

Total number of instrumented lines.

lines-percent

Line coverage percentage formatted with one decimal place (e.g. 85.7).

functions-covered

Number of functions with non-zero execution count.

functions-total

Total number of instrumented functions.

functions-percent

Function coverage percentage formatted with one decimal place (e.g. 92.3).

branches-covered

Number of branches with non-zero execution count.

branches-total

Total number of instrumented branches.

branches-percent

Branch coverage percentage formatted with one decimal place (e.g. 70.1).

new-lines-covered

Number of new or modified lines with non-zero execution count. Zero if diff analysis is unavailable.

new-lines-total

Total number of new or modified instrumented lines. Zero if diff analysis is unavailable.

new-lines-percent

New-code line coverage percentage formatted with one decimal place. Zero if diff analysis is unavailable.

new-functions-covered

Number of covered new/modified functions. Zero if diff analysis is unavailable.

new-functions-total

Total number of new/modified instrumented functions. Zero if diff analysis is unavailable.

new-functions-percent

New-code function coverage percentage formatted with one decimal place. Zero if diff analysis is unavailable.

new-branches-covered

Number of covered new/modified branches. Zero if diff analysis is unavailable.

new-branches-total

Total number of new/modified instrumented branches. Zero if diff analysis is unavailable.

new-branches-percent

New-code branch coverage percentage formatted with one decimal place. Zero if diff analysis is unavailable.
